# AI 发现张量网络收缩顺序算法

本项目研究一个问题：Coding Agent 能否编写可复用的收缩顺序搜索算法，并在不同张量网络上取得比人工基线更好的结果？

Agent 生成的是**搜索算法代码**。算法接收张量网络，输出收缩顺序。独立评估器检查顺序是否合法，再计算该顺序的收缩代价。项目不以优化单个固定网络为最终目标。

详细目标和研究边界见[项目介绍](详细要求介绍.md)；主指标与计分约定见[实验指标与评估规则](实验指标与评估规则.md)；各阶段进展和决定记录在[完整设计](完整设计.md)。

## 当前状态

最小实验已接入 OpenEvolve。固定实例、评估器、Greedy、Random-Greedy 和模拟退火基线已运行。本机模拟模型完成两轮反馈检查；真实 SiliconFlow 模型生成过一份候选代码，但候选在全部开发实例上执行失败。更强模型的一次完整生成请求超时。当前没有优于基线的有效候选。证据和限制见[阶段报告](提交材料/阶段报告.md)，运行说明见[实验目录](../experiment/README.md)。

## 核心流程

```text
固定网络实例 → Agent 生成算法代码 → 限时执行并得到收缩顺序
                                      ↓
上一轮结果 ← 保留有效候选 ← 独立评估器校验并计分
```

模块职责分开：

| 模块 | 职责 |
| --- | --- |
| 实例集 | 提供固定的电路和格点网络，以及生成参数 |
| 候选接口 | 规定算法的输入、输出、随机种子和时间预算 |
| 生成器 | 根据历史反馈编写或修改算法代码 |
| 执行器 | 运行候选代码，记录超时、异常和耗时 |
| 评估器 | 校验收缩顺序，统一计算代价；候选代码不能修改它 |
| 选择器与循环 | 比较结果、保存候选、组织下一轮 |

## 实施顺序

1. **固定问题与评估器**：确定网络和收缩顺序的数据格式、代价定义、合法性检查。用已知小例子验证结果。
2. **建立基线**：固定少量训练实例和随机种子，运行 Greedy；记录每个实例的代价与搜索时间。
3. **跑通自动循环**：先用真实模型生成一轮，再扩展到 5–10 轮，保存每轮代码、分数、错误、时间和配置。此阶段不要求超过基线。
4. **做可信比较**：加入更强的基线、相同的搜索预算和独立测试实例。报告各实例结果及总体指标，并检查算法能否泛化。

## 框架选择

首轮选择 OpenEvolve，因为当前 Windows 环境已完成接入和本地模拟测试。ShinkaEvolve 和 CodeEvolve 仍是后续对照候选；这不是搜索效果优劣的结论。框架负责候选代码的生成、保存和迭代；张量网络计分规则由本项目定义。选择依据见[完整设计](完整设计.md)。

## 首个可运行版本的完成标准

- 相同实例、路径和评估配置得到相同代价。
- 无效路径、异常和超时有明确结果，不会被当作改进。
- 一次命令可完成测试和 Agent 搜索，并保存可追溯记录；调整后的多轮真实运行仍待验证。
- 候选算法与基线使用同一评估器；报告同时包含收缩代价和找路径的时间。

评估器计算的是**给定收缩顺序的代价**，不是整个问题的全局最优值。一次实验中的改进，也不能直接证明算法在其他网络上有效。
