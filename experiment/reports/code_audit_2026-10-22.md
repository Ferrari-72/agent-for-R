# 代码与实验审计（2026-10-22）

## 范围

检查候选接口、OpenEvolve 交接、容器边界、路径计分、请求预算、最终测试冻结和已有真实实验。此审计不把已有最终集结果用于候选修改。

## 已发现并修复

1. **计时信任边界。** 候选子进程原先能上报并篡改 `search_seconds`。现在受信任父进程覆盖该值，用于 10 秒检查和报告。子进程函数计时仅保留为 `function_seconds_untrusted` 诊断值。容器测试让候选篡改自己的计时函数后，父进程计时仍正确。
2. **模型请求预算口径。** 旧报告直接读取共享数据库累计次数，不能把 26 次解释为该运行独有请求。现在正式脚本在探测前记录请求 ID，报告同时写入 `request_count_before`、`request_count_after`、`requests_added_this_run` 和 `budget_db_cumulative_count`。正式模式缺少持久预算数据库即报错；运行脚本不再提供换库参数。历史上三个真实预算库已有 30、9、6 条请求记录，合计 45 条；这超出原计划的项目总上限，不能事后消除。
3. **旧运行的源码留存。** 已完成的五轮真实实验保存了最佳候选与规则哈希，但没有保存全部当时的规则源码；当时的镜像 ID 也已不在 Docker 本机。现在新运行会保存规则源码、开发数据与清单，最终评估时再保存最终/迁移数据；准备脚本为镜像保留源码哈希标签。此修复不追溯补足旧运行。
4. **最终评估中断。** 原入口先写一次性标记，中途失败后无法继续。现在逐例落盘，重启时只评估缺失实例，并核对已保存结果顺序、候选哈希、规则哈希、镜像 ID 与数据清单哈希。
5. **错误反馈。** traceback 尾部空行曾让导入异常的具体原因丢失。现在提取最后一个非空异常行。补丁解析、补丁未匹配、语法、导入、非法路径和错误 API 已用假模型两轮重放；失败候选未入库，下一轮收到对应反馈。

## 可核验结果

- 项目单元测试：31 项通过。
- Docker 检查：无网络、无 API 密钥、无法读取最终数据、只读根文件系统、超时、内存限制及候选篡改计时均通过。
- 旧真实运行 `evolve_20261022T233306Z_d86aa8`：5 次候选尝试，3 次有效；最终电路 24/24 次候选试验有效，候选代价与逐例最优预设基线之比的几何平均为 1.4143245357394398；格点迁移 18/18 次有效，比值为 1.2924906678419315。两组均未优于该基线。
- `verify_saved_report.py` 对旧最终报告 84 条基线和候选路径复算：路径合法性、`cotengra` 代价/峰值、独立索引维度计数、逐例比值及汇总均一致。结果见该运行目录的 `independent_recheck.json`。本复算没有重新执行候选，也没有验证旧运行时间。

## 尚未证明

- 当前新版源码快照流程还没有完成一次新的五轮真实模型运行及最终测试；旧运行不能替代这项验证。
- 旧运行报告中的 26 次请求是当时共享预算库的累计值，不是该次运行独有的请求数。
- 只有一次五轮真实搜索，不能据此推断算法的稳定胜率，也不能推断 Agent 一般能力。

## 下一步改进方向

1. 经单独批准新请求预算后，用固定协议完成多次独立真实运行，并报告运行间方差和有效候选率。
2. 扩大电路宽度、深度和种子，并按规模分层分析；继续保持新的最终集对搜索不可见。
3. 增加对较大网络的独立代价校验和已知最优小例，区分实现错误与搜索能力不足。
4. 在同一容器边界记录实际峰值内存、CPU 时间和镜像/依赖归档，便于跨机器重放。
5. 将候选改进策略做成事先登记的单变量实验，例如单独比较反馈格式、确定性搜索策略或种群选择；不要在看过最终集后调参。

## 新进度复审

- 新增了 runner 镜像归档、研究流程文档和经验记录校验器。33 项项目测试通过，但当前 runner 镜像的源码标签仍是 `f11bf2...`，当前源码哈希为 `027733...`；正式运行脚本会拒绝旧镜像。下一次正式实验前需重建镜像并重新核对标签。
- `research_summary` 原先会把旧报告共享数据库累计的 26 次请求写成“本次新增”。现改为旧报告显示“未知”，并说明不能反推；新增回归检查。最终报告的 `scope` 也不再无条件声称一次运行受 30 次总请求约束。
- 经验分类与校验目前只有独立函数和局部测试，尚未接入每轮 journal、反馈或经验检索。不能称为已验证的经验反馈机制。该模块现列入源码快照。
- 新请求字段以运行前的最后 ID 和报告时的数据库计数求差。如果多个运行同时写入同一数据库，此值会包含其他运行请求。正式研究应为每条请求持久记录 `run_id` 并禁止或明确处理并发，才能得到精确归因。
- 镜像归档有哈希与测试，但还缺从归档加载镜像、在另一台机器执行并比对逐例结果的演练。归档存在不等于跨机器可复现。

## 2026-10-23 续审结果
